# ADR-010: React + Vite como UI mínima de onboarding

## Estado

Aceptada

Fecha: 2026-04-30

## Contexto

El alcance original (§6) excluía UI propia porque Swagger alcanzaba para uso interno técnico. Las decisiones del PO del 2026-04-30 introducen multi-tenancy con login Microsoft SSO y un servidor MCP que cada usuario debe configurar en su cliente Claude (Code o Desktop). Hace falta una superficie web mínima para: (1) ejecutar el flow OAuth contra Microsoft Entra ID, (2) mostrar al usuario las instrucciones y credenciales para configurar su Claude. **No es una "app" — es una pantalla de onboarding**. El grueso de la interacción del usuario ocurre dentro de su Claude vía MCP, no en la web.

## Opciones Consideradas

| Opción | Descripción | Pros | Contras |
|---|---|---|---|
| A: React + Vite (SPA mínima) | 2-3 páginas: login, mcp-setup, (opcional) historial | Ramp-up rápido, ecosistema enorme, build sencillo, servible como StaticFiles | Build step en Dockerfile; requiere disciplina de scope para no inflar a "app" |
| B: HTMX + Jinja2 templates | Server-rendered con HTMX para interacciones | Sin build step, más simple en Python puro | Menos familiar para devs JS; tooling más artesanal |
| C: CLI-only | El usuario corre `transcription-api login` desde su terminal | Cero UI web | Fricción para users no técnicos; rompe el flujo OAuth web |
| D: Sin UI, configuración manual | Admin emite tokens y los pasa al user | Cero código frontend | Operativamente insoportable a partir de 3 users |

## Decisión

Se elige **Opción A (React + Vite con scope estrictamente acotado)**. Justificación anclada en Simplicidad (prioridad #2): React es el toolkit más estándar y menos sorprendente; Vite es el bundler más rápido y de configuración mínima.

**Scope obligatorio**:

- `/login` — botón "Iniciar sesión con Microsoft", redirige al OAuth de Entra.
- `/auth/callback` — recibe el code, lo intercambia por tokens vía backend, setea cookie de sesión, redirige a `/mcp-setup`.
- `/mcp-setup` — muestra al user logueado:
  - URL del MCP server (`https://<rig>:8000/mcp`).
  - Bearer token personal vinculado a su identidad.
  - Snippet listo para copiar para `claude_desktop_config.json` y `.mcp.json` (Claude Code).
  - Botón "regenerar token" (revoca el anterior).
- (Opcional, fase 2) `/history` — listado de sus transcripciones recientes con borrar/exportar.

**Scope explícitamente prohibido sin nuevo ADR**:

- Subir audio o imágenes desde la UI (esos van por Claude → MCP → REST upload).
- Generar minutas en la UI (eso ocurre en Claude del user, ver ADR-012).
- Configuración avanzada del pipeline (idioma, hablantes) desde la UI (parámetros pasan por la tool MCP).
- Administración multi-rol, gestión de usuarios.

**Stack**:

- React 18 (sin upgrade a 19 hasta que ecosystem se estabilice).
- Vite 5 como bundler.
- Routing: `react-router-dom` (3 rutas, no necesita más).
- Styling: Tailwind CSS 3 (utility-first; sin design system pesado).
- Sin estado global (Zustand, Redux): React state local alcanza para 3 páginas.
- Build output: `dist/` servido por FastAPI vía `StaticFiles` mount en `/` (no hay nginx separado).

## Consecuencias

**Positivas**:
- Onboarding del user es 1-2 clics: `/login` → MS SSO → `/mcp-setup` → copiar config.
- Stack frontend estándar; cualquier dev moderno puede contribuir.
- Sin servidor frontend separado: Dockerfile produce el build de React durante el image build y FastAPI sirve los estáticos.
- Refactor a futuro: si se quisiera reemplazar React por otro framework, la superficie es chica.

**Negativas**:
- Dockerfile sumar etapa de build de Node 20 + npm install + vite build (agrega ~3 minutos al primer build).
- Mitigación: multi-stage Dockerfile separa builder Node de runtime Python (la imagen final solo tiene los estáticos).
- Riesgo de scope creep — la presión de agregar features a la UI puede crecer.
- Mitigación: este ADR explicita el "scope prohibido"; cualquier feature nueva requiere ADR de extensión.

**Neutras**:
- Estilos consistentes con la imagen corporativa de Sandinas se pueden agregar más adelante (logo, colores) sin cambiar la arquitectura.
