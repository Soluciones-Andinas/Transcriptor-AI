# ADR-005: Lock global para concurrencia (1 request a la vez)

## Estado

Aceptada

Fecha: 2026-04-30

## Contexto

El rig tiene una única GPU con 16 GB VRAM. Whisper large-v3 + pyannote 3.1 cargados en memoria consumen ~12 GB. Procesar dos requests simultáneos excede VRAM y crashea el proceso (CUDA out of memory). Hay tres patrones para manejar concurrencia: lock global (1 a la vez), cola con worker único, cola con N workers (no aplica con 1 GPU). Volumen esperado: ~20 reuniones/mes; concurrencia esperada cercana a cero.

## Opciones Consideradas

| Opción | Descripción | Pros | Contras |
|---|---|---|---|
| A: Lock global (asyncio.Semaphore o threading.Lock) | El segundo request espera al primero o recibe 503 | Implementación trivial (10 líneas); sin estado persistente | Si segundo cliente espera mucho, su HTTP timeout puede saltar |
| B: Cola con Redis + 1 worker | Requests entran a Redis queue; un worker procesa de a uno | Maneja backpressure; el cliente recibe job ID y polea | Viola ADR-003 (síncrono) y ADR-004 (sin Redis); excesivo |
| C: Sin control (best-effort) | Cualquier número de requests; CUDA crashea si hay choque | Simpleza máxima | Inaceptable: un segundo upload simultáneo crashea el servicio entero |

## Decisión

Se elige **Opción A (lock global con respuesta 503 si está ocupado)**. Implementación con `asyncio.Lock` o `asyncio.Semaphore(1)` en el endpoint `POST /transcribe`. Si el segundo request intenta tomar el lock y supera un timeout corto (ej. 5 segundos), responde HTTP 503 Service Unavailable con header `Retry-After: 600` (10 minutos). El cliente decide si reintentar.

Alineado con Simplicidad (prioridad #2) y consistente con ADR-003 (síncrono) y ADR-004 (sin DB/Redis).

## Consecuencias

**Positivas:**
- Implementación trivial; sin nuevas dependencias.
- Ningún choque de VRAM posible.
- Comportamiento predecible: 1 request → 1 procesamiento.

**Negativas:**
- Throughput máximo limitado a ~5 reuniones por hora (asumiendo 12 min/reunión). Mitigación: aceptable para 20 reuniones/mes.
- Cliente debe manejar el caso 503 con reintento (mitigación: documentar en README + Swagger).

**Neutras:**
- Si en futuro hace falta procesar paralelo, hay dos caminos: sumar GPU al rig (cambio de hardware), o particionar en 2 procesos cada uno con su modelo en memoria (requiere 24 GB+ VRAM total). Ambos disparan ADR de reemplazo.
