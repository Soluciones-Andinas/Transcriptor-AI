# ADR-006: Docker + nvidia-container-toolkit como mecanismo de deployment

## Estado

Aceptada

Fecha: 2026-04-30

## Contexto

El servicio combina dependencias delicadas: PyTorch + CUDA toolkit + cuDNN + ffmpeg + Python 3.10/3.11 + WhisperX + pyannote. Una mala combinación de versiones produce errores difíciles de diagnosticar (segfaults, CUDA mismatches). El rig se administra por una sola persona y debe ser reproducible: si se reinstala el OS, levantar el servicio debe ser un comando. Prioridad del proyecto: **Privacidad > Simplicidad > Calidad > Performance > Costo**.

## Opciones Consideradas

| Opción | Descripción | Pros | Contras |
|---|---|---|---|
| A: Docker + nvidia-container-toolkit | Imagen reproducible con todo el stack; volúmenes para modelos | Reproducibilidad; aislamiento; rebuild trivial; estándar de industria | Imagen pesada (~8 GB); requiere nvidia-container-toolkit instalado one-time |
| B: virtualenv + dependencias del host | Python venv con `pip install -r requirements.txt` directo en el host | Sin overhead de container; debug más directo | Pollution del sistema; no reproducible; pesadilla con CUDA versions |
| C: conda env | Ambiente conda con paquetes binarios de NVIDIA | Maneja CUDA versions mejor que pip | Conda es más lento; sigue siendo pollution del host |
| D: Kubernetes | Cluster K8s con pods para el servicio | Auto-recovery, rolling updates | Excesivo para un solo nodo y un único microservicio |

## Decisión

Se elige **Opción A (Docker + nvidia-container-toolkit)**. Alineado con Simplicidad (prioridad #2) y reproducibilidad operativa. Stack:

- Imagen base: `nvidia/cuda:12.1.1-cudnn8-runtime-ubuntu22.04` (D-058: el Dockerfile fija el patch `.1`; las wheels CUDA 12.1.x son ABI-compatibles).
- `Dockerfile` instala Python, ffmpeg, dependencias del proyecto.
- `docker-compose.yml` orquesta el servicio con GPU pass-through (`runtime: nvidia` o equivalente moderno).
- Volúmenes:
  - `./models:/models` (modelos cacheados, persisten entre rebuilds).
  - `./cache:/cache` (caché filesystem 24 h, persiste entre rebuilds).
- Levantar: `docker compose up -d`.
- Logs: `docker compose logs -f`.

## Consecuencias

**Positivas:**
- Reproducibilidad: cualquier rig con Docker + nvidia-container-toolkit corre el servicio igual.
- Aislamiento: dependencias Python no contaminan el host.
- Modelos descargados persisten en volumen; rebuild de imagen no los re-descarga.
- Estandar para deployment de servicios IA con GPU.

**Negativas:**
- Imagen pesada (~8 GB). Mitigación: build una vez por release; el costo de descarga es one-time.
- Requiere nvidia-container-toolkit instalado en el host (one-time setup). Mitigación: documentar en `DEPLOYMENT.md`.
- Build time inicial ~10-15 min. Mitigación: rebuilds usando cache de capas son rápidos.

**Neutras:**
- Si se cambia la GPU del rig, basta con reinstalar driver y nvidia-container-toolkit; el servicio levanta sin tocar código.
